# 字幕时轴校准台

本地运行的字幕时间轴校准工具：导入 SRT 后，在任意字幕上录入「原时间 → 目标时间」校准锚点，系统按**相邻锚点分段线性映射**、**首尾区间沿最近一段斜率外推**，实时预览新时间；检测到冲突时禁止导出。还可做**字幕断行排版**（字素簇级列宽 + 动态规划，只动换行）、导入**本地音频**做「对白覆盖审计」，在浏览器内检出「有声无字幕」与「疑似空挂」字幕并导出 JSON 报告，在当前源 SRT 上导入译文 SRT 做**双语字幕合成**（按时间区间正长度交集配对、每组导出一条），以及对当前正文做**批量校订**（区分大小写的字面量查找 / 替换，先预览后整批应用，仅存内存）。前端为原生 HTML/CSS/JavaScript，后端为 Python FastAPI，所有数据仅保存在本地浏览器与内存中。

## 功能

- **导入 SRT**：选择本地文件或直接粘贴文本（UTF-8），容错 BOM、`\r\n`、时间行定位属性。
- **校准锚点**：在任意字幕行点击「⚑ 锚点」，录入原时间与目标时间；锚点可删除。
- **分段线性映射**：至少 2 个锚点启用；相邻锚点间线性插值，首锚点之前 / 末锚点之后分别沿最近一段斜率外推；不足 2 个锚点时按原始时间预览。
- **实时预览**：字幕表中并列显示原时间与新时间，每次锚点/锁定变更后立即刷新。
- **冲突拦截**：出现以下任一情况时标红对应字幕并**禁止导出**：
  - 映射后出现负时间；
  - 结束时间不晚于开始时间；
  - 相邻字幕时间重叠；
  - 锚点原时间重复 / 锚点目标时间为负。
- **锁定字幕**：点击「🔒 锁定」后该字幕保留原时间、不参与映射（仍参与重叠检查）。
- **撤销**：「↩ 撤销锚点/锁定」可逐步回退最近的锚点（添加/删除）或锁定/解锁操作。
- **导出**：无冲突时导出 UTF-8 编码的 SRT（重新从 1 顺序编号）。
- **字幕断行排版（第 6 步）**：设置每行 **12～30 列**、**最多 1～3 行**后批量生成断行建议，页面逐条对照原文与建议，可**单条接受**、**全部接受**，并可**一次撤销本轮**结果。排版**只增删换行、或把断点处一个空白替换为换行**，不改其他字符顺序、时间轴、锚点、锁定与 `.stc` 指纹；另提供**排版版 SRT 下载**（只写入已接受的换行，普通导出保持原样）。算法与规则详见下文「字幕断行排版规则」。
- **`.stc` 校准工程（跨会话）**：把当前锚点、锁定项、撤销栈保存为 `.stc`（UTF-8 JSON）文件；下次先导入 SRT 再打开工程即可恢复。同一文件直接恢复；字幕重排/重新编号时按条目指纹迁移并展示旧→新编号映射；无法一一对应时列明原因并拒绝，当前工作区保持不变。
- **对白覆盖审计（第 5 步，纯本地）**：导入本地音频后，浏览器用 Web Audio API 解码（**音频绝不上传**，后端也不提供任何音频接口），按当前**实时预览时间轴**做区间扫描：
  - **语音检测**：按 **20ms 窗口**对各声道分别计算 RMS，每窗取跨声道最大值；以**整段 RMS 峰值 × 可调阈值**（滑块，默认 5%）判定有声；**桥接短于 120ms 的静音**、**剔除短于 80ms 的有声片段**；
  - **有声无字幕**：落在所有字幕区间之外、连续 **≥300ms** 的语音区间；
  - **疑似空挂**：字幕区间内**静音占比 ≥70%** 的字幕；
  - **自动重算**：锚点 / 锁定变化导致实时预览刷新、阈值滑块变化、或重新导入音频 / SRT 后自动重算；
  - **波形叠加层**：Canvas 波形上方叠加字幕条（疑似空挂为橙底红边）、绿色语音区间块、定位高亮与红色播放头；点击结果行或波形可**定位**并**试听区间（点击点）前后各 1 秒**，可随时停止；
  - **核听记录**：每条结果可标记 / 取消「☑ 已核听」（重算后按区间 / 条目保留），导出的 JSON 报告含**音频摘要**（文件名、大小、时长、声道、采样率、SHA-256）、**参数**、语音区间、两类结果与每项**核听状态**。
- **双语字幕合成（第 7 步）**：在当前源 SRT 上导入一份**译文 SRT**，系统按两侧**原始时间区间的正长度交集**配对（`max(起) < min(止)`，**端点相接不算**）：
  - **传递成组**：相交关系按连通分量传递（s1∩t1、s2∩t1 ⇒ {s1,s2,t1} 同组），多对一 / 一对多合并为同一组，**每条字幕只出现一次**；分组按源字幕顺序排列；
  - **译文校验**：译文 SRT 存在**时间倒挂**（结束不晚于开始）或任意两条**正长度重叠**（端点相接允许）时**拒绝导入**，并列明原因，当前配对保持不变；
  - **页面展示**：按源字幕顺序展示每个配对组（组内分列源文 / 译文各条及其原时间），以及两侧**未配对条目**（源侧按源顺序穿插、译文侧单列一区）；
  - **双语导出拦截**：任一侧存在未配对条目，或实时预览存在冲突（或尚未刷新）时，**禁止双语导出**；
  - **双语 SRT**：每组生成一条，正文为组内**源文各条按原顺序换行拼接**、**译文各条按原顺序换行拼接**后上下排列（仅换行分隔，不插空行）；时间取该组源字幕**当前校准预览**的最早开始与最晚结束，**译文时间只参与配对**；
  - 锚点 / 锁定变化导致实时预览刷新后自动更新各组导出时间；**重新导入源 SRT 清空旧配对**（重新导入译文则覆盖旧配对）；配对仅用于双语导出，**普通导出 / 排版版导出 / `.stc` 工程均保持原样、不含译文**。
- **批量校订正文（第 8 步，纯本地内存）**：输入**非空查找词**与**替换文本**（可空＝删除命中），选择**源文 / 译文 / 两者**，在当前正文中按**区分大小写的字面量**、**从左至右**替换**不重叠命中**；两项输入**均不得含换行**。先逐条列出修改前后文本，确认后**整批应用**：
  - **只改正文**：不改时间、编号、锚点、锁定，也不改**原始 SRT 摘要与条目指纹**；源字幕被改正文时，只清除**该条**的排版建议、已接受换行与本轮排版撤销记录（其他条目保留，排版撤销不会复活旧正文；在途迟到的排版请求按旧正文作废）；
  - **整批应用的失效拦截**：预览后若任一侧**成功重新导入**（源文或译文）或**待改正文发生变化**，拒绝整批应用且工作区不变；仅锚点 / 锁定变化（不动正文）仍可应用；
  - 页面展示与**普通 / 排版版 / 双语三种下载**都使用**校订后正文**，原有冲突拦截与双语未配对拦截保持不变；
  - **生命周期**：校订**仅存浏览器内存**，不发起网络请求；`.stc` 工程**不保存**校订、恢复工程**不回退**当前正文；**成功重导源文清空两侧校订**，**重导译文仅清空译文侧校订**，译文导入失败则保留原状态。

## 浏览器音频格式限制（重要）

对白覆盖审计依赖浏览器的 `AudioContext.decodeAudioData`，**能解码哪些格式完全取决于你的浏览器与操作系统**，本工具（含后端）不内置任何解码器、也不做转码：

- Chrome / Edge（桌面）通常支持：WAV（PCM）、MP3、AAC（`.m4a`/`.mp4` 音频轨）、FLAC、Ogg Vorbis/Opus（Opus 支持因容器而异）；
- Firefox 通常支持：WAV、MP3、FLAC、Ogg Vorbis/Opus；AAC/m4a 依赖系统编解码器（Windows/macOS 一般可用，部分 Linux 需额外安装）；
- Safari 通常支持：WAV、MP3、AAC(m4a)；FLAC/Ogg 支持较新系统版本才有。

若导入后提示「浏览器无法解码该音频」，请先用本地工具（如 ffmpeg）转码为兼容性最好的 **WAV（16-bit PCM）或 MP3** 再导入。声道数、采样率不限，解码后按原始采样率计算；音频解码可能占用与文件大小相当的内存，请避免导入体积过大的文件。计算 SHA-256 摘要需要浏览器的 Web Crypto（`crypto.subtle`，https 或 localhost 下可用），不可用时摘要留空但不影响审计。

## 快速开始（Docker，一条命令）

```bash
docker compose up --build
```

然后在浏览器访问：**http://localhost:8000**

停止：`Ctrl+C`，或 `docker compose down`。

## 本地开发（不用 Docker）

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

访问 **http://127.0.0.1:8000**

## 使用流程

1. 点击「选择 SRT 文件」导入字幕（或点「载入示例」先体验）。
2. 在字幕行点击「⚑ 锚点」，确认/修改原时间，输入目标时间，添加锚点；至少设置 2 个。
3. 表格「新开始 / 新结束」列实时显示映射结果；右侧「冲突检查」列出所有问题。
4. 需要保留原时间的字幕点「🔒 锁定」；误操作用「↩ 撤销」回退。
5. 无冲突时点击「⬇ 导出 SRT」下载 UTF-8 SRT 文件。
6. 需要跨会话继续时点「💾 保存工程 .stc」；下次先导入同一份 SRT，再点「📂 打开工程 .stc」恢复（详见下文）。
7. （可选）在第 6 步「字幕断行排版」设置每行 12～30 列、最多 1～3 行，生成建议后逐条或全部接受，需要时点「📐 下载排版版 SRT」；普通「⬇ 导出 SRT」始终不含排版换行。
8. （可选）在第 5 步「对白覆盖审计」选择本地音频：检查「有声无字幕」与「疑似空挂」，逐条定位、试听中点前后 1 秒、标记已核听，最后「⬇ 导出审计 JSON 报告」。
9. （可选）在第 7 步「双语字幕合成」选择（或粘贴）与当前源 SRT 对应的译文 SRT：页面按源顺序展示配对组与两侧未配对条目；确认无未配对、第 4 步无冲突后点「🌐 导出双语 SRT」。译文时间倒挂 / 重叠会被拒绝导入；重新导入源 SRT 会清空配对。
10. （可选）在第 8 步「批量校订正文」输入非空查找词与替换文本（替换可空），选择源文 / 译文 / 两者，点「预览修改」逐条核对，确认后「整批应用」。校订仅存内存，不写入 `.stc`，重导 / 刷新页面即失效。

时间输入支持 `HH:MM:SS,mmm`、`HH:MM:SS.mmm`、`MM:SS.mmm`、纯秒数（如 `75.5`）。

## 映射规则

设锚点按原时间升序为 `(o₁,t₁)…(oₙ,tₙ)`（n ≥ 2）：

- `oᵢ ≤ o ≤ oᵢ₊₁`：`f(o) = tᵢ + (o − oᵢ) · (tᵢ₊₁ − tᵢ) / (oᵢ₊₁ − oᵢ)`
- `o < o₁`：沿第一段 `(o₁,t₁)-(o₂,t₂)` 的斜率外推
- `o > oₙ`：沿末段 `(oₙ₋₁,tₙ₋₁)-(oₙ,tₙ)` 的斜率外推

锁定的字幕不参与映射，直接保留原时间。

## `.stc` 校准工程

工具栏「💾 保存工程 .stc」会把当前工作区序列化为一个 UTF-8 JSON 文件（扩展名 `.stc`）；「📂 打开工程 .stc」在**当前已导入的 SRT** 上恢复它。工程不内嵌完整 SRT，只保存恢复所需的最小信息：

```json
{
  "schema_version": 1,
  "source": { "sha256": "<原始 SRT 文本的 UTF-8 SHA-256>", "subtitle_count": 12 },
  "subtitles": [
    { "id": 1, "start_ms": 1000, "end_ms": 3000, "fingerprint": "<条目指纹>" }
  ],
  "anchors": [{ "id": 1, "subtitle_id": 1, "original_ms": 1000, "target_ms": 1500 }],
  "locks": [3],
  "history": [{ "anchors": [], "locks": [3] }],
  "anchor_seq": 2,
  "saved_at": "2026-09-18T00:00:00+00:00"
}
```

- **原始摘要**：`source.sha256` 是导入时**原始 SRT 字节文本**（BOM、CRLF 原样保留）的 UTF-8 SHA-256，用于判断是否为同一文件。
- **条目指纹**：每条字幕的指纹为 `SHA-256("{start_ms}|{end_ms}|{NFC+LF 归一化正文}")`。指纹只取决于该条自身的时间与文本，与它在文件中的序号无关，因此块顺序调整、重新编号、行尾差异（CRLF/BOM）、Unicode 组合形式差异（NFD→NFC）都不影响匹配。

### 恢复路径

打开工程时以**当前工作区的 SRT** 为准：

1. **原文件恢复**：当前 SRT 的 SHA-256 与工程 `source.sha256` 相同 → 直接沿用原编号恢复锚点、锁定、撤销栈。
2. **重排迁移**：摘要不同 → **禁止沿用旧 id**，改为按条目指纹逐条匹配当前 SRT。只有所有被**锚点、锁定项、撤销栈快照**引用的字幕都在当前 SRT 中找到**唯一**指纹候选（一一对应）后才迁移；页面以表格展示旧编号 → 新编号映射（含引用来源：锚点/锁定/撤销栈），锚点自身 id 与原时间/目标时间保持不变。
3. **拒绝（工作区不改变）**：以下任一情况都会以红面板列明全部原因，且不会修改当前任何状态：
   - **缺失项**：被引用条目的指纹在当前 SRT 中不存在；
   - **重复候选**：一个旧条目在当前 SRT 中有多个同指纹条目，无法唯一确定；
   - **未知 schema**：`schema_version` 不是工具支持的版本（当前为 `1`）；
   - **非法摘要 / 非法结构**：`sha256`/`fingerprint` 不是 64 位十六进制、字段类型错误、时间倒挂、工程内部引用悬空等；
   - 当前 SRT 无法解析为有效 SRT。

恢复（含迁移）成功后，实时预览、撤销栈、SRT 导出结果与保存前一致（同一映射作用到对应条目）。

### 使用示例

- **原文件恢复**：`ep01.srt` 上校准到一半 → 保存 `ep01.stc`；次日重新导入同一份 `ep01.srt` → 打开 `ep01.stc`，绿面板提示「原文件恢复完成」。
- **重排迁移**：对方把 SRT 块顺序重排、重新编号后发回（文本与时间未变）→ 导入新版本后打开旧 `.stc`，工具按指纹迁移并展示如 `旧 #3 → 新 #7` 的映射表，锚点/锁定/撤销栈随之落到新编号。
- **拒绝案例**：新版本删了一条被锚点引用的字幕（缺失项），或同一时间+文本的字幕在新文件中出现两次（重复候选）→ 红面板逐条列明原因，当前锚点/锁定/撤销栈保持原状，可修正 SRT 后重试。

## 字幕断行排版规则

排版只允许三类编辑，**其他字符的内容与顺序、时间轴、锚点、锁定、`.stc` 条目指纹都不变**：

1. 在候选断点处**新增**换行；
2. **保留 / 删除**正文里既有的换行；
3. 把断点处的**一个空白字素簇替换**为换行（该空白不再保留）。

服务端导出时还会对每条已接受的建议做字素簇级双指针对齐校验，任何换行以外的改动（改字、加字、删字、在非候选位置断行、行首/行尾禁则）都会拒绝导出。

**字素簇与列宽**

- 用第三方库 [`regex`](https://pypi.org/project/regex/) 的 `\X` 切分 Unicode 字素簇：emoji ZWJ 序列（如 👨‍👩‍👧‍👦）、组合音标 / 声调（如 `e` + combining acute）、变体选择符等都**作为整体、绝不拆开**；
- 用 [`wcwidth`](https://pypi.org/project/wcwidth/) 的 `wcwidth.wcswidth` 计算每个字素簇的列宽（汉字 / 全角字符 2 列，ASCII 1 列；换行、制表等控制字符按 0 列）。

**候选断点（限于三类；既有换行始终可保留）**

- **空白处**：该空白字素簇被换行替换，不计入行宽、不出现在结果里；
- **标点之后**：前一内容字素簇是 Unicode 标点（`\p{P}`）；
- **相邻汉字之间**：前后均为汉字（`\p{Han}`）。

**断点罚分**（从优到劣）

| 断点类型 | 罚分 |
| --- | --- |
| 句末标点 `。！？；` 之后 | 0 |
| 空白（替换为换行） | 1 |
| 其他标点之后（含逗号、引号等） | 2 |
| 相邻汉字之间 | 3 |

既有换行若落在上述允许位置，按对应类型计分；落在非允许位置（如外文字母与汉字之间）时作为**兜底断点**（罚分 4），仅用于保留原文换行、让排版在严格参数下仍可能有解。

**行首 / 行尾禁则**

- 禁止 `，。！？；：、）》】」』` 出现在行首；
- 禁止 `（《【「『` 留在行尾。

**动态规划的目标（三级字典序）**

只接受**所有行均不超过列宽**的方案（每行至少含一个内容字素簇，不产生空行）；在全部可行方案中依次最小化：

1. **总罚分**（各断点罚分之和）；
2. **各行剩余列数的平方和**（`Σ(列宽 − 该行实际宽)²`，使各行更均衡、更接近充满）；
3. **断点位置字典序**（以上两者相同时，断点元组字典序更靠前的方案，即更倾向于尽早断行）。

**无解说辞**：任何列宽 / 行数设置下都无解时，该条标记为「无解」并逐条列明原因，例如：

- 最少需要的行数超过「最多 N 行」；
- 自某个字素簇起没有任何可合法结束本行的断点，连续片段宽 X 列超过每行上限；
- 正文以禁止出现在行首的标点开头 / 以禁止留在行尾的标点结尾（固有违规）；
- 单个字素簇自身宽度就超过每行列宽（字素簇不可拆）。

**接受、撤销与下载**

- 「生成排版建议」开启**一轮**排版：可逐条「✔ 接受此条」或「✔ 全部接受」（仅接受可行且确有改动的条目），接受后字幕表正文格出现 📐 标记；
- 「↩ 撤销本轮」一次性把接受状态恢复到本轮生成建议之前；重新生成建议即开启新一轮；
- 「📐 下载排版版 SRT」：时间仍走当前锚点 / 锁定的实时预览映射（与普通导出一样做冲突检查），正文**只对已接受条目写入换行，其余条目原样**；未接受任何换行或存在冲突时按钮禁用；
- 工具栏普通「⬇ 导出 SRT」始终导出**原始正文**；排版状态**不写入 `.stc` 工程**（`.stc` 仍只保存锚点、锁定、撤销栈，指纹不变）。

## 双语字幕合成规则

在第 7 步对当前源 SRT 导入一份译文 SRT（文件或粘贴，均为 UTF-8），配对只使用两侧的**原始时间区间**：

**配对（正长度交集 + 传递成组）**

- 源条目 `[aₛ,aₑ)` 与译文条目 `[bₛ,bₑ)` 当且仅当 `max(aₛ,bₛ) < min(aₑ,bₑ)` 时相交；一条的结束恰好等于另一条的开始（端点相接）**不算**；
- 相交关系按**连通分量**（并查集）传递：s1∩t1、s2∩t1 ⇒ {s1,s2,t1} 是同一组；
- 多对一、一对多、多对多只要经相交连通就合并成一组，**每条源 / 译文字幕在结果中恰好出现一次**（要么在某个组里，要么列入本侧未配对）；
- 分组按组内**最早源条目**在源 SRT 中的顺序排列。

**译文导入校验（任一不满足即拒绝导入，当前配对不变）**

- 单条时间倒挂：`end_ms ≤ start_ms`；
- 任意两条译文区间存在正长度重叠（端点相接允许，完全包含也算重叠）。

**页面展示**

- 按源字幕顺序遍历：配对组在其首个源条目位置展示一张组卡（组内分「源文」「译文」两列，各条标注原编号与原时间）；未配对源条目以红卡片穿插在对应位置；
- 未配对译文条目按译文自身顺序单列在「译文侧未配对条目」区；
- 组卡标题显示该组**双语导出时间**（组内源字幕当前校准预览的最早开始 / 最晚结束）。

**双语导出**

- 拦截条件：译文未导入、任一侧存在未配对条目、实时预览存在冲突（含映射后负时间 / 倒挂 / 相邻重叠）、或导入译文后预览尚未刷新；
- 每组生成一条 SRT（重新从 1 编号）：
  - 正文 = 组内源文各条按源顺序以换行拼接，换行后再接组内译文各条按译文顺序的换行拼接（源文块在上、译文块在下，**仅换行分隔，不插空行**）；
  - 时间 = `min(组内各源条目 新开始)` → `max(组内各源条目 新结束)`，其中「新开始 / 新结束」取**当前锚点 / 锁定的实时预览**；**译文时间只参与配对，绝不进入导出时间轴**；
- 文件名形如 `<源文件名>.bilingual.srt`。

**生命周期与边界**

- 锚点 / 锁定变化后实时预览刷新，组卡导出时间与导出按钮状态同步更新；
- 重新导入源 SRT（文件或粘贴 / 载入示例）会**清空旧配对与已导入译文**；重新导入译文则覆盖旧配对；
- 译文与配对关系仅保存在浏览器内存中，用于页面展示与双语导出：**不写入 `.stc` 工程**（`.stc` 仍只保存锚点、锁定、撤销栈，源 SRT 指纹不变），普通「⬇ 导出 SRT」与「📐 下载排版版 SRT」的内容也**完全不受**译文影响。

## 批量校订正文规则

第 8 步在**当前工作区正文**（源文为当前字幕表正文，译文为第 7 步已导入译文正文）上做批量查找 / 替换，整个过程不发起任何网络请求：

**输入与匹配**

- **查找词必填非空**，**替换文本可空**（空＝删除命中，即把命中替换为空字符串）；两项**均不得含换行**（不跨行校订，粘贴到单行输入框即被限制，程序侧也会再次拦截 `\n` / `\r`）。
- **区分大小写**的**字面量**匹配：不是正则、不忽略大小写，查找词中的 `$`、`.`、`（` 等字符都按普通字符处理。
- 对每条正文按**从左至右**顺序替换**不重叠命中**（等价于以查找词切分后用替换文本拼接，替换文本中即使出现查找词也不会再次匹配）。

**预览与整批应用**

- 点「预览修改」后，按所选侧（**仅源文 / 仅译文 / 两者**）逐条列出**修改前 → 修改后**正文与命中处数，未命中的条目不列出；没有任何命中时提示且不产生待应用批次。
- 确认后点「✔ 整批应用」一次性落地全部改动，或「取消」放弃；预览期间正文不改变。
- **失效拦截**：从预览到应用之间，若任一侧**成功重新导入**（源文重导或译文重导），或批次内任一条**待改正文发生了变化**，则拒绝整批应用、工作区不做任何改动并要求重新预览；**仅锚点 / 锁定变化不改正文，仍可应用**。

**落地影响**

- **只改正文**：时间、编号、锚点、锁定、原始 SRT 字节摘要（`state.rawContent` 的 SHA-256）与 `.stc` 条目指纹都不改动；
- 源字幕正文被改时，只清除**被改条目**的断行排版建议、已接受换行与本轮排版撤销快照，**其他排版条目保留**；排版撤销因此**不可能复活旧正文**，应用前发出、此刻才迟到的排版建议响应也按旧正文作废；
- 页面字幕表、配对组卡立即显示校订后正文；**普通 SRT、排版版 SRT、双语 SRT 三种下载都使用校订后正文**，原有的冲突拦截、双语未配对拦截保持不变（译文编号 / 时间不动，配对关系不重新计算）。

**生命周期（与工程文件的关系）**

- 校订**只保存在浏览器内存中**：刷新页面即失效；`.stc` 工程只保存锚点、锁定、撤销栈，**不保存任何正文校订**；
- 在已校订的 SRT 上「📂 打开工程 .stc」恢复，只改变锚点 / 锁定 / 撤销栈，**不会把当前正文回退**到工程保存时的旧文本；
- **成功重新导入源 SRT**（文件 / 粘贴 / 载入示例）→ 清空**两侧**（源文 + 译文）校订；**成功重新导入译文 SRT** → 仅清空**译文侧**校订（源文校订保留）；译文因时间倒挂 / 重叠被拒绝导入时，译文校订与配对都**保留原状态**。

## 对白覆盖审计算法

1. **分窗 RMS**：窗长 20ms（`窗口数 = floor(采样数 / (采样率 × 0.02))`），每个窗口对每个声道计算 `√(mean(x²))`，再取各声道 RMS 的**最大值**作为该窗口能量；
2. **阈值判定**：取所有窗口 RMS 的整段峰值 `peak`，窗口能量 `≥ peak × 阈值比例` 即有声（阈值比例滑块可调，默认 0.05）；
3. **形态处理**：连续有声窗口合并为语音段 → **桥接静音间隙严格短于 120ms 的相邻段** → **剔除时长严格短于 80ms 的片段**（边界恰好 120ms 不桥接、恰好 80ms 保留）；
4. **区间扫描**（时间轴取实时预览的**新时间**，裁剪到 `[0, 音频时长]`）：
   - 字幕区间取并集，其补集与语音区间求交，连续时长 **≥300ms** 的交集记为「有声无字幕」；
   - 对每条字幕求其区间与语音区间的交集时长，`静音占比 = 1 − 语音时长 / 字幕时长`，**≥0.70** 记为「疑似空挂」。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 前端页面 |
| POST | `/api/parse` | `{content}` → 解析 SRT，返回字幕列表与原文 `sha256` |
| POST | `/api/preview` | `{subtitles, anchors, locks}` → 映射结果、冲突列表、`can_export` |
| POST | `/api/export` | 同上；有冲突返回 400，否则返回 UTF-8 SRT 文件（正文原样） |
| POST | `/api/bilingual/pair` | `{subtitles, translations}` → 校验译文时间（倒挂 / 正长度重叠，端点相接允许）并按原始区间正长度交集配对，返回 `groups`、两侧未配对 id 与 `complete`；译文不合法返回 400，`detail = {code:"invalid_translation", message, reasons[]}` |
| POST | `/api/bilingual/export` | `{subtitles, translations, anchors, locks}` → 译文校验 + 冲突拦截 + 两侧必须全部配对，返回双语 SRT（每组一条，时间取源字幕当前预览的组内最早开始 / 最晚结束）；任一不满足返回 400 |
| POST | `/api/typeset/suggest` | `{subtitles, columns, maxLines}` → 逐条断行排版建议（无解条目附原因） |
| POST | `/api/typeset/export` | `{subtitles（含 original_text）, anchors, locks}` → 冲突拦截 + 字素簇级校验后返回排版版 SRT |
| POST | `/api/project/save` | `{content, anchors, locks, history, anchor_seq, saved_at?}` → `.stc` 工程 JSON |
| POST | `/api/project/load` | `{content, project}` → 恢复/迁移结果；无法一一对应时返回 400，`detail = {code, message, reasons[]}` |

工程恢复错误码：`unknown_schema`（未知 schema）、`invalid_digest`/`invalid_project`（非法摘要或结构）、`current_invalid`（当前 SRT 无法解析）、`migration_failed`（缺失项 / 重复候选等，原因在 `reasons` 中逐条给出）。

时间均以毫秒整数传递。
